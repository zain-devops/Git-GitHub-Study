# 🧪 Practice Labs

Use a separate repository or disposable folder for each lab.

## Lab 1 — Personal notes repository

**Goal:** practise the basics.

1. Initialize a repository.
2. Add `README.md`, `goals.md`, and `resources.md`.
3. Commit each logical change.
4. Inspect history and diffs.
5. Add a `.gitignore` and a harmless `notes.tmp` file.

**Done when:** you can explain each commit and identify staged vs unstaged changes.

## Lab 2 — Feature branch

**Goal:** practise branching and merging.

1. Create a branch `feature/about`.
2. Add `about.md`.
3. Commit the change.
4. Switch back to `main`.
5. Merge the branch.
6. Inspect the history graph.

## Lab 3 — GitHub publication

**Goal:** publish a local project.

1. Create an empty GitHub repository.
2. Connect it as `origin`.
3. Push `main`.
4. Edit README on your computer.
5. Commit and push the update.
6. Clone the repository into a second folder.

## Lab 4 — Pull request

**Goal:** practise collaboration.

1. Create a feature branch.
2. Make a documentation improvement.
3. Push the branch.
4. Open a pull request.
5. Write a summary and review the diff.
6. Merge when ready.

## Lab 5 — Conflict resolution

**Goal:** understand conflicts.

Create two branches from the same base and edit the same line differently. Commit each change, merge the branches, resolve the conflict, and inspect the final result.

## Capstone — Publish a complete learning repository

Build a GitHub repository that contains:
- A well-structured README
- Lesson folders
- A cheat sheet
- Exercises and answers
- Official learning links
- A `.gitignore`
- At least 5 meaningful commits
- One feature branch and merged pull request (if possible)

### Capstone review rubric

| Area | Target |
|---|---|
| Structure | Clear folder names and navigation |
| Documentation | Accurate, readable, useful |
| Git history | Focused commits with meaningful messages |
| Collaboration | Branch and PR workflow demonstrated |
| Safety | No secrets or confidential files |
