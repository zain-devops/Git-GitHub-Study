# 12 — GitHub Flow, Issues and Pull Requests

## GitHub Flow

1. Create a branch.
2. Make changes and commit them.
3. Push the branch.
4. Open a pull request.
5. Discuss and review the diff.
6. Make requested updates.
7. Merge when approved and checks pass.
8. Delete the branch if it is no longer needed.

## Issues

Issues track bugs, tasks, questions and improvements. A useful issue includes context, expected behavior, actual behavior when relevant, steps to reproduce, and acceptance criteria.

## Pull requests

A pull request (PR) proposes changes for discussion and review. It is a GitHub feature, not a Git command.

A good PR description explains:
- What changed?
- Why was it needed?
- How was it tested?
- Are there screenshots or additional notes?

## Review checklist

- [ ] Does the change solve the stated problem?
- [ ] Is the code/documentation clear?
- [ ] Are there unintended changes?
- [ ] Are secrets or personal data exposed?
- [ ] Are tests or checks passing?
- [ ] Is the documentation updated where needed?
